# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Senpi/OMO extension (`extension/routing.ts`, `routing-policy.ts`, `routing-runtime.ts`, `routing-signals.ts`) that registers `/routing`: an interactive TUI editor and temporary routing policy manager for `~/.omo/omo.jsonc`. README.md is the authoritative spec: command forms, editor behavior, config resolution order, write rules. Read it before changing behavior. README.ko.md is its Korean translation: every behavior change to README.md must be mirrored there in the same commit.

## Commands

```sh
node --test                                   # all tests (Node >= 22.6; .mjs tests import the .ts via built-in type stripping; run inside omo or set OMO_BIN: fixtures borrow omo-ai's @babel/parser and one test reads the installed bundles)
node --test --test-name-pattern="profile"     # single test by name substring
omo install <path-to-this-clone>              # install the working tree as an omo package (users: omo install git:github.com/yjacket/omo-routing), then /reload
```

No build step, no lint, no dependencies. Never test against a live paid OMO session; the fake `pi`/`ctx` harnesses (`test/editor-command.test.mjs` with a fake `ui.custom` and model registry, `test/editor-fixture.mjs`) are the only runtime used. A live check of `/routing` sends no prompt: slash commands never reach the model.

## Architecture

- `extension/routing.ts` exports pure helpers (`stripJsonc`, `parseJsonc`, `mergeConfig`, `resolveProfileName`, `profileNames`, `applyProfile`, `chainOf`, `loadBuiltinRouting`, `resolveRouting`, `parseEditorArgs`, `setJsoncPath`/`removeJsoncPath`, and the editor helpers below) and `createRouting(pi, deps)`, which registers `/routing`. The default export just calls `createRouting`. `deps` injects `env`, `home` and `cwd` (where project `.omo/omo.jsonc` files are looked for; default `ctx.cwd`) for tests.
- Command forms: `/routing [--profile <p>|-p <p>|--base]` opens the editor (TUI only; elsewhere an error). `/routing edit ...` is the same command under its former name. Policy commands: `/routing policy` (show the policy state), `/routing refresh`, `/routing promo on|off`, `/routing codex on|off`. Anything else is an error naming the options; an unknown profile name is an error listing the available profiles. The report/widget, the `models` view, `help`/`off` and `set|prepend|add|remove` were removed on 2026-09-29 at the user's request (the editor covers them); do not bring them back without one.
- JSONC writes: `parseJsoncTree` is a position-aware JSONC parser (comments blanked to spaces so offsets hold); `setJsoncPath` replaces an existing value keeping its inline/multiline style, or inserts a nested literal at the deepest existing object with the surrounding indentation; `removeJsoncPath` removes only the member and one separating comma, so neighbouring comments survive. Each mutation re-parses, so no offset bookkeeping across edits. Written layer: profile (or base) `[native]` when present, else a legacy `[senpi]` when present, else a new `[native]` unless the layer keeps routing keys at its root.
- Editor: `editorNodes` (every node with its builtin chain, each layer's own `Override` via `layerEntry`/`overrideOf`, and the effective chain), `availabilityOf(ctx.modelRegistry)` + `rungView` (connected providers; hidden rungs), `effortLevels` (host `getSupportedThinkingLevels` imported by file from the installed pi-ai by `hostThinkingLevels`: senpi's nested copy under omo-ai's `node_modules`, or beside omo-ai where a bun global install hoists it; else model metadata), `workingChain`, `chainWarnings`. `RoutingEditor` is a pi-tui component (`render`/`handleInput`/`invalidate`) opened with `ctx.ui.custom(..., { overlay: true, overlayOptions: EDITOR_OVERLAY })`; keys go through `decodeKey` (legacy, xterm and kitty CSI-u; ctrl/alt chords ignored); every rendered line is exactly the width (`fitCells`), framed (`╭─ title ─╮`, `│ … │`, `├──┤` rules) when at least 20 wide and 10 rows tall, with a description column while the chain keeps 36 cells; its height stays put across nodes and views (body = the list's length, fixed 8-row detail pane, key help and status reserve their longest variant) and stays within 80% of the rows (not more: omo renders inline below the shell prompt, so right after launch the top rows of the frame are off-screen and a taller centered overlay loses its title; seen live 2026-09-25). It never writes: `EditorDraft`s (per layer; `chain: null` = follow, `disable: null` = drop) go to `saveConfig` → `applyDrafts` (the write-target rule above, removes `model`/`fallback_models`, prunes empty entries, external-change guard, `.bak` of the pre-session file on the first save only, creates a missing file); `applyDraftsToConfig` is the in-memory preview and walks own keys only (a `__proto__` profile is refused). OMO hot-reloads omo.jsonc on change (senpi's config-reload builtin, seen live 2026-09-25), and a reload tears the overlay down, so `session_before_reload` returns `{ cancel: true, reason: EDITOR_RELOAD_VETO }` while the editor is open; the host defers, rechecks every second and reloads once it closes. Builtin drift: `builtinSnapshot`/`snapshotDrift`/`mergeSnapshot` with `~/.omo/routing-builtin-snapshot.json`, written when an editor open finds sections the snapshot lacks (all of them the first time) and on `c`. `projectConfigs` mirrors OMO's project config walk (cwd upward, stopping before home); `projectNotice` words its header warning.
- Temporary policies: `routing-policy.ts` `composePolicies` puts the OpenGateway DeepSeek rung first for `quick`/`explore`/`librarian` while the discount is >= 90%, until 15 min before the known end, and a manual Codex preference moves existing `chatgpt-subscription`/`openai-codex` rungs first without adding models; it runs after inheritance, for base and every saved profile. `unwrapPolicies` reverts a receipt holding only the policy-owned edits, compare-and-restore, so a user edit to the same spot wins. `routing-runtime.ts` `RoutingPolicies` keeps settings, cached signals and the receipt in `~/.omo/routing-policies.json`; a pending receipt is published before the config write, a mkdir lock guards writes (waits up to 2 s for a holder; its directory is removed when older than 30 s), tmp+rename replacement retries EPERM/EACCES/EBUSY for 2 s (on Windows a Bun reader blocks it), an unchanged recomposition writes nothing (every idle session recomposes after an omo.jsonc reload), a refresh is claimed at most once a minute, and failures keep the cache. `routing-signals.ts` does public GETs of `opengateway.ai/api/model-prices` and `codex-reset.com/api/forecast` with the `omo-routing` User-Agent, renders the `omo-routing` footer status (Codex part: only the documented `latest_alert`, an active Watch's score and deadline or a reset confirmed within 24 h; the forecast is shown by `/routing policy` only), and builds the hidden `routing-policy` custom message tagged `routing-promo-nudge`/`routing-promo-end`. Wiring in `routing.ts`: `session_start` starts an unref'd one-minute refresh timer and skips writes while the editor is open; `before_agent_start` sends the nudge; the editor edits the unwrapped base and shows the policy result; `saveConfig` recomposes through `RoutingPolicies.write`.
- Config resolution mirrors `omo-task.js`: profile = `OMO_PROFILE` → `OCX_PROFILE` → `OPENCODE_CONFIG_DIR` tail; layers base → `[native]` → profile base → profile `[native]`, where a layer without `[native]` uses its legacy `[senpi]` (OMO renames `[senpi]`→`[native]` on load and drops it when both exist); objects deep-merge, arrays replace; `__proto__`/`constructor`/`prototype` keys are skipped.
- Builtin defaults: `loadBuiltinRouting(env)` parses `omo-task.js` (categories, agents, category inheritance) and `omo.js` (main model profiles) under `OMO_BIN/../plugin/extensions` with omo-ai's own `@babel/parser` (`createRequire` from the install root; `require(esm)`, so the loader stays synchronous). Tables are found by AST shape; only constant-data nodes (`isConstant`) are evaluated in a `vm` context, spreads bound from same-name array literals that must agree. Each section fails on its own into `defaults.unavailable` (an editor warning; those nodes show configured chains only); the result is cached by bundle content hash. OMO exports neither these tables nor its resolvers (`Pg`/`Jg`/`resolveModelForDelegateTask` are sealed in the bundle, checked on beta.89), so there is nothing to call instead. After an OMO upgrade, `node --test` inside omo checks the installed bundles.
- Scope is deliberately trimmed: the editor reads `ctx.modelRegistry.getAvailable()` only to hide unconnected providers and offer models (explicit user request, 2026-09-25). The only network reads are the two public policy endpoints above. Nothing reads `auth.json` or `credential-pool-state.json`. Do not add further provider-state checks without an explicit user request. No profile switch: the profile is fixed by the environment at host start.

## Conventions

- Tests drive the command end to end through the fake harness; add a test for every new command form, editor behavior, or resolution rule.
- Commit messages follow `routing: <what changed>`.
